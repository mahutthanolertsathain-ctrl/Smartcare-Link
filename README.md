# ระบบสุขภาพชุมชน — local prototype

ต้นแบบนี้รวมหน้าผู้ป่วย, อสม., รพ.สต./รพช. และเทศบาลไว้ในเว็บเซิร์ฟเวอร์ local เดียว ใช้ Python standard library และ SQLite ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

## เริ่มระบบ

เปิด PowerShell ที่โฟลเดอร์ `D:\med\MED` แล้วรัน:

```powershell
python main.py
```

เปิด `http://127.0.0.1:8000/` ในเบราว์เซอร์ ครั้งแรกจะพาไป `/setup` เพื่อสร้างบัญชีเจ้าของระบบ (รหัสผ่านอย่างน้อย 12 ตัวอักษร) หลังจากนั้นจึงล็อกอินและเลือกหน้าใช้งานตามบทบาทได้ ปิดเซิร์ฟเวอร์ด้วย `Ctrl+C`

ข้อมูลจากโทรศัพท์และคอมพิวเตอร์จะใช้ SQLite ชุดเดียวกันบนเครื่องที่รันเซิร์ฟเวอร์ จึงต้องเปิดเครื่องและเปิดเซิร์ฟเวอร์ไว้จึงจะใช้งานจากอุปกรณ์อื่นได้

## หน้าระบบ

- `/` หน้าหลักเลือกทางเข้าแยกผู้ป่วย/ญาติ, อสม., รพ.สต./รพช., เทศบาล และคู่มืออบรม
- `/screening` แบบประเมินอาการและรับคิว
- `/patient` ประวัติผู้ป่วย ค่าวัด ขอเยี่ยมบ้าน ขอเติมยา/ความช่วยเหลือ และ SOS พร้อม GPS หรือหมุดแผนที่
- `/community` ทะเบียน Single Patient Record พร้อมปักหมุดบ้าน, ค่าวัด, งานเยี่ยมบ้าน, คำขอยา/สวัสดิการ และเริ่ม video call
- `/nurse` บอร์ดคิวและเหตุแจ้งเตือนสำหรับ รพ.สต./รพช.
- `/dispatch` บอร์ด SOS, ทะเบียนหน่วยพร้อมปักหมุดฐานรถ, จับคู่หน่วยที่พร้อมและใกล้ที่สุดจากพิกัด
- `/telemedicine` ห้อง video call แบบ WebRTC สำหรับสาธิตในเครื่องเดียว
- `/training` บทเรียนการใช้ระบบและความคืบหน้าสำหรับ 4 บทบาท

เริ่มสาธิตได้โดยสร้าง HN สมมติ เช่น `DEMO-001` ที่หน้า `/community` แล้วใช้ HN เดียวกันใน `/patient` หรือหน้าคัดกรอง

## ขอบเขตและความปลอดภัย

- เซิร์ฟเวอร์ bind เฉพาะ `127.0.0.1`; มีบัญชีเจ้าของระบบและ session หมดอายุใน 12 ชั่วโมง พร้อมจำกัดความถี่การลองล็อกอิน แต่ยังไม่มีบัญชีแยกตามบทบาท/ผู้ป่วยหรือ audit log ทุกคนที่มีบัญชีนี้จะเห็นข้อมูลทั้งหมด
- หน้าเว็บยังเป็นต้นแบบสำหรับข้อมูลทดสอบ ห้ามใส่ข้อมูลสุขภาพจริงหรือใช้ปฏิบัติงานจริงจนกว่าจะทบทวนสิทธิ์รายบทบาท, audit log, การสำรอง/กู้คืน, การป้องกันอุปกรณ์ และมาตรการคุ้มครองข้อมูลโดยหน่วยงาน
- Cloudflare Quick Tunnel เปิดให้เข้าถึงหน้า login จากอินเทอร์เน็ตโดยไม่ใช้ OTP ตามที่ตั้งค่าไว้; API และหน้าข้อมูลยังบังคับล็อกอินในเว็บ การรับส่งข้อมูลผ่าน Cloudflare และลิงก์ชั่วคราวจะเปลี่ยนเมื่อเริ่ม Tunnel ใหม่ ใช้ข้อมูลทดสอบเท่านั้น
- ใน `/community` เจ้าของระบบลบระเบียนผู้ป่วยได้โดยพิมพ์ HN ยืนยัน; การลบครอบคลุมประวัติ ค่าวัด คิว งาน และห้อง telemedicine ทั้งหมดของผู้ป่วย รวมถึงห้องที่ยังเปิดอยู่และสัญญาณที่เกี่ยวข้อง ส่วน SOS/คิว/งานที่กำลังดำเนินการยังต้องปิดงานก่อนจึงลบได้
- SOS บันทึกและแสดงในบอร์ด local เท่านั้น ไม่ได้โทรแจ้ง 1669, ส่ง SMS, ส่งข้อมูลให้เทศบาล/โรงพยาบาลจริง หรือเรียกรถจริง ผู้ใช้ต้องโทร 1669 เองเมื่อเกิดเหตุฉุกเฉิน
- แผนที่เลือกตำแหน่งใช้ Leaflet และแผนที่ OpenStreetMap; การเปิดดูแผนที่จะทำให้ OpenStreetMap เห็นพื้นที่แผนที่โดยประมาณ ไม่มีการ reverse-geocode หรือส่งข้อมูลผู้ป่วยไปค้นหาที่อยู่
- พิกัดบ้านผู้ป่วยและ SOS เป็นข้อมูลละเอียดอ่อน เก็บในฐานข้อมูล local; หลีกเลี่ยงข้อมูลจริงจนกว่าจะมีมาตรการคุ้มครองข้อมูลที่เหมาะสม
- การจับคู่รถใช้ระยะทางเส้นตรงจากพิกัดฐาน ไม่ได้ดูเส้นทาง การจราจร หรือความเหมาะสมทางการแพทย์
- การคัดกรองเป็นข้อมูลเบื้องต้นและต้องให้บุคลากรทางการแพทย์ประเมิน ไม่ใช่การวินิจฉัย
- ห้องวิดีโอมี signaling local และไม่มี TURN server จึงเป็นการสาธิต ไม่รับประกันการเชื่อมต่อข้ามเครือข่าย
- ฐานข้อมูล local อยู่ที่ `triage.db`; สำรองไฟล์ก่อนย้ายเครื่องหรือแก้ schema

ก่อนใช้กับบริการจริงต้องมีการยืนยันตัวตน/สิทธิ์เข้าถึงแบบรายบทบาท, การปกป้องข้อมูล, การทบทวนแนวทางคัดกรองโดยบุคลากร, และการเชื่อมต่อที่ได้รับอนุญาตจากหน่วยงานปลายทาง
