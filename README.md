# Smartcare Link — ระบบดูแลสุขภาพชุมชน

Smartcare Link เป็นเว็บแอปต้นแบบสำหรับสาธิตแนวคิดการประสานงานดูแลสุขภาพในชุมชน เชื่อมข้อมูลและขั้นตอนทำงานระหว่าง **ผู้ป่วย/ญาติ, อสม., รพ.สต./รพช. และเทศบาล** ให้เห็นภาพการส่งต่อข้อมูลตั้งแต่คัดกรองอาการ ติดตามสุขภาพ ไปจนถึงประสานเหตุฉุกเฉิน

## จุดประสงค์ของโปรแกรม

โครงการนี้จัดทำขึ้นเพื่อศึกษาและนำเสนอว่าเทคโนโลยีเว็บและการพัฒนาซอฟต์แวร์สามารถช่วยให้การทำงานด้านสุขภาพชุมชนต่อเนื่องและประสานกันได้อย่างไร ผู้จัดทำต้องการเรียนรู้การออกแบบระบบ การพัฒนาเว็บ การเชื่อมต่อฐานข้อมูล การใช้ตำแหน่งบนแผนที่ และการออกแบบประสบการณ์ใช้งานบนโทรศัพท์ แท็บเล็ต และคอมพิวเตอร์

ระบบจำลองแนวทางการทำงาน เช่น ใช้ระเบียนผู้ป่วยตัวอย่างร่วมกัน บันทึกค่าความดัน/น้ำตาล ส่งคำขอเยี่ยมบ้าน รับคิวจากการคัดกรอง และแสดงเหตุ SOS บนบอร์ดประสานงาน ทั้งหมดนี้เป็น **ต้นแบบเพื่อการศึกษาและสาธิตผลงาน** ไม่ใช่ระบบเวชระเบียนหรือบริการฉุกเฉินที่ผ่านการรับรอง

## ทดลองใช้งานออนไลน์

เปิด [Smartcare Link](https://smartcare-link.vercel.app/) ได้จากโทรศัพท์ แท็บเล็ต หรือคอมพิวเตอร์ หน้าเว็บปรับตามขนาดหน้าจอและเลือกกลุ่มผู้ใช้งานจากหน้าแรก

> เว็บอาจตอบสนองช้าเป็นบางช่วง เนื่องจากใช้โฮสต์และบริการฐานข้อมูลบนแพ็กเกจฟรี ซึ่งอาจมีข้อจำกัดด้านทรัพยากรหรือพักการทำงานเมื่อไม่มีผู้ใช้

## หน้าหลักของระบบ

| หน้า | หน้าที่ |
| --- | --- |
| `/` | หน้าเริ่มต้น เลือกทางเข้าตามกลุ่มผู้ใช้งาน |
| `/screening` | แบบประเมินอาการเบื้องต้นและออกหมายเลขคิว |
| `/patient` | หน้าผู้ป่วย/ญาติ ดูข้อมูลสุขภาพ ส่งคำขอ และแจ้ง SOS พร้อมตำแหน่งหรือหมุดแผนที่ |
| `/community` | ทะเบียนผู้ป่วยตัวอย่าง (Single Patient Record), บันทึกค่าความดัน/น้ำตาล จัดการเยี่ยมบ้าน คำขอช่วยเหลือ และประสาน Telemedicine |
| `/nurse` | บอร์ดคิวและรายการแจ้งเหตุสำหรับเจ้าหน้าที่ ใช้เรียกคิวและติดตามสถานะ |
| `/dispatch` | บอร์ด SOS และทะเบียนหน่วย/รถสำหรับจำลองการจัดสรรทรัพยากรตามตำแหน่ง |
| `/telemedicine` | ห้องวิดีโอคอลสำหรับทดลองการปรึกษาทางไกล |
| `/training` | บทเรียนและแนวทางใช้งานสำหรับกลุ่มผู้ปฏิบัติงาน |

## การแจ้งเตือนคิว

หลังผู้ป่วยทำแบบประเมินและได้รับคิว ระบบสามารถแสดงข้อความและแจ้งเตือนเมื่อเจ้าหน้าที่เรียกคิวได้ โดยเปิดหน้าคัดกรองค้างไว้และกด **“ขออนุญาตแจ้งเตือน”** เพื่ออนุญาตให้เบราว์เซอร์แสดงการแจ้งเตือน

- ระบบต้นแบบตรวจสถานะคิวขณะหน้าเว็บทำงาน การแจ้งเตือนจึงอาจไม่มาถึงเมื่อปิดหน้าเว็บหรือปิดแอป
- บน iPhone/iPad ให้เปิดเว็บด้วย Safari แล้วเลือก **แชร์ → เพิ่มไปยังหน้าจอโฮม** จากนั้นเปิดเว็บผ่านไอคอนที่เพิ่มไว้และกดขออนุญาตแจ้งเตือน ระบบ iOS/iPadOS รองรับการขอสิทธิ์ Web Push สำหรับเว็บแอปบนหน้าจอโฮมตั้งแต่เวอร์ชัน 16.4 เป็นต้นไป แต่โปรเจกต์นี้ยังไม่ได้เชื่อมผู้ส่ง Push จากเซิร์ฟเวอร์
- ปัจจุบันยังไม่ได้เชื่อมระบบส่ง Push จากเซิร์ฟเวอร์, SMS หรือ LINE การแจ้งเตือนเมื่อปิดเว็บจึงยังไม่ใช่ฟังก์ชันที่รับประกันว่าจะทำงาน

## เทคโนโลยีและการทำงาน

- Frontend ใช้ HTML, CSS และ JavaScript ออกแบบให้เปิดผ่านเว็บบนหลายขนาดหน้าจอ
- Backend ใช้ Python ใน `main.py` และมี Vercel adapter ที่ `api/index.py`
- ฐานข้อมูลในเครื่องใช้ SQLite (`triage.db`) ส่วนตอน deploy บน Vercel ต้องกำหนด `DATABASE_URL` เพื่อเชื่อม PostgreSQL ผ่าน `vercel_db.py` (โครงการนี้เตรียมใช้งานกับฐานข้อมูล Neon)
- แผนที่ใช้ Leaflet และ OpenStreetMap ซึ่งเป็นบริการภายนอกและต้องเชื่อมต่ออินเทอร์เน็ต
- ห้องวิดีโอใช้ WebRTC เพื่อสาธิตการเชื่อมต่อระหว่างเบราว์เซอร์
- `vercel.json` ระบุเส้นทางและการตั้งค่า deploy ของ Vercel ส่วน `requirements.txt` ระบุไลบรารี Python ที่ต้องติดตั้ง

## เปิดเซิร์ฟเวอร์สำหรับพัฒนาในเครื่อง

ต้องติดตั้ง Python 3 ก่อน จากนั้นเปิด PowerShell ในโฟลเดอร์โปรเจกต์และรัน:

```powershell
python main.py
```

เปิด `http://127.0.0.1:8000/` บนเครื่องที่รันเซิร์ฟเวอร์ แล้วกด `Ctrl+C` ใน PowerShell เพื่อหยุดเซิร์ฟเวอร์ โหมดนี้ใช้ SQLite ในเครื่องและเปิดผ่าน `127.0.0.1` ได้เฉพาะเครื่องนั้น หากต้องการทดสอบการเชื่อมต่อ PostgreSQL ให้ติดตั้งไลบรารีด้วย `python -m pip install -r requirements.txt` และกำหนด `DATABASE_URL` ก่อนรัน การเปิดเว็บให้โทรศัพท์หรือแท็บเล็ตใช้งานผ่านอินเทอร์เน็ตต้องใช้ deployment บนโฮสต์ เช่น Vercel

## ข้อจำกัดและความปลอดภัย

- **หน้าเว็บและ API เปิดสาธารณะโดยไม่มี Login หรือการแยกสิทธิ์ผู้ใช้** ผู้ที่มีลิงก์อาจดู เพิ่ม แก้ไข หรือลบข้อมูลในระบบได้
- ใช้ข้อมูลสมมติเท่านั้น ห้ามกรอกชื่อจริง HN/เลขบัตรประชาชน เบอร์โทร โรค ยา หรือพิกัดบ้านของผู้ป่วยจริง
- การคัดกรองเป็นเพียงการประเมินเบื้องต้น ไม่ใช่การวินิจฉัยหรือคำแนะนำแทนบุคลากรทางการแพทย์
- SOS ในเว็บเป็นการบันทึกเหตุเพื่อสาธิต ไม่ได้โทร 1669 ไม่ได้ส่งคำขอไปยังโรงพยาบาลหรือเทศบาลจริง และไม่ได้สั่งรถพยาบาล หากเกิดเหตุฉุกเฉินให้โทร **1669** โดยตรง
- การจับคู่หน่วยใช้ตำแหน่งและระยะทางเส้นตรงโดยประมาณ ไม่ได้คำนวณเส้นทาง การจราจร หรือความเหมาะสมทางการแพทย์
- วิดีโอคอลเป็นฟังก์ชันทดลอง คุณภาพและการเชื่อมต่อขึ้นกับเครือข่ายและเบราว์เซอร์
- ฐานข้อมูลบนบริการฟรีอาจมีโควตา การพักระบบ หรือข้อจำกัดการเก็บรักษาข้อมูล ควรสำรองข้อมูลทดสอบที่จำเป็นและไม่ใช้เป็นแหล่งเก็บข้อมูลจริง

ก่อนนำแนวคิดไปใช้จริง ต้องพัฒนาการยืนยันตัวตนและสิทธิ์ตามบทบาท การบันทึกประวัติการเข้าถึง การสำรองและกู้คืนข้อมูล การรักษาความปลอดภัย และให้หน่วยงาน/ผู้เชี่ยวชาญตรวจสอบกระบวนการทางการแพทย์และการคุ้มครองข้อมูลก่อน
